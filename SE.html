Key Concepts for Part II:

  • Software Crisis: Late 60s era of over-budget, unreliable software.
  • Verification vs Validation: "Building product right" (Process) vs "Building right product" (User needs).
  • Regression Testing: Re-testing after changes to ensure no new bugs.
  • Information Hiding: Hiding internal details, exposing only interfaces (reduces coupling).
  • Cyclomatic Complexity: Metric for code complexity. Formula: V(G) = E - N + 2.

Key Concepts for Part III:

  • Waterfall Limits: No feedback path, rigid, high risk if reqs change.
  • Integration Rule: Top-down uses stubs (tests main logic first). Bottom-up uses drivers (tests components first).
  • Equivalence Class: Divide input into valid/invalid classes. Test one from each.
  • CMM Levels: Initial, Managed, Defined, Quantitatively Managed, Optimizing.

4(c). Define Cohesion and Coupling. Explain types. Why is Low Coupling desirable? ★ [6]

Memory Hook:

Cohesion: "Do one thing well" (Internal). Coupling: "Dependency" (External).

Best to Worst (Cohesion): Functional > Sequential > ... > Coincidental.

Best to Worst (Coupling): Data > Stamp > ... > Content.

Differentiation Table:

Boundary Value Analysis (BVA):

A Black Box technique based on testing the "edges" of input ranges. Example: If range is 1-100, test 0, 1, 100, 101. Errors mostly hide at boundaries.
